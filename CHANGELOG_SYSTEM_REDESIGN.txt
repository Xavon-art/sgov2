Phase 9 - Notifications
- Added src/lib/notifications-server.ts for unit/owner recipient lookup, actor exclusion, deduplication, and create_notification fan-out.
- Added task creation, task thread, personal request submission, and personal request decision notices from the API boundary.
- Added supabase/migrations/20260101005100_notification_flow_links.sql with legacy-function wrappers for task submission, task decisions, budget requests/reviews, extensions, events/claims, event assignments, accomplishment reports/reviews, survey closure, and stale link backfill.
- Added item-focused deep links in RequestSection, ReviewQueuePanel, UsgBudgetPanel, LsgBudgetPanel, EventsWorkspace, AccomplishmentPanel, and MessagesPanel.
- Updated the feature map so F23 documents the completed notification flows and canonical destinations.
- Notification workflow:
  1. USG creates a task: assigned LSG unit officers receive task_created, opening /lsg/request?tab=tasks&task=<taskId>.
  2. Either side posts in a task thread: the other side receives task_thread_message, opening the task with thread=1.
  3. LSG submits a task for review: USG reviewers receive task_submitted, opening /usg/request?tab=review with the task selected.
  4. USG approves, returns, or rejects a requirement/item: the filing LSG unit receives task_requirement_*, opening /lsg/request?tab=tasks&task=<taskId>.
  5. LSG files or resubmits a personal request: USG receives personal_request_submitted, opening /usg/request?tab=personal&request=<requestId>.
  6. USG decides or the LSG withdraws a personal request: the correct side receives personal_request_decided, opening /{side}/request?tab=personal&request=<requestId>.
  7. LSG submits a budget request: USG receives budget_submitted, opening /usg/manage?tab=budget&budgetTab=review&budget=<budgetId>.
  8. USG reviews a budget request: LSG receives budget_*, opening /lsg/manage?tab=budget&budgetTab=overview&budget=<budgetId>.
  9. LSG requests an extension: USG receives task_extension_requested, opening /usg/request?tab=review&task=<taskId>.
  10. USG decides an extension: LSG receives task_extension_approved or task_extension_rejected, opening /lsg/request?tab=tasks&task=<taskId>.
  11. USG publishes an event: LSG receives event_published, opening /lsg/events?event=<eventId>&action=claim.
  12. LSG claims an event: USG receives event_claim, opening /usg/events?event=<eventId>&action=decide.
  13. USG honours or rejects a claim: LSG receives event_honored or event_not_honored, opening /lsg/events?event=<eventId>.
  14. USG assigns an event reporter: LSG receives event_assigned, opening /lsg/events?tab=accomplishment&event=<eventId>&action=report.
  15. LSG submits an accomplishment report: USG receives accomplishment_report_submitted, opening /usg/events?tab=accomplishment&report=<reportId>.
  16. USG acknowledges or returns an accomplishment report: LSG receives accomplishment_report_acknowledged or accomplishment_report_returned, opening /lsg/events?tab=accomplishment&report=<reportId>.
  17. A direct message is sent: every other participant receives message, opening /{side}/messages?c=<conversationId>&m=<messageId>.
  18. A survey closes: the creator receives survey_closed, opening /{side}/forms?type=survey&id=<surveyId>.
